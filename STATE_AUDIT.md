# Аудит UseAbstract, GlobalStore и AppContext

## Обнаружено и исправлено

| Файл | Подтверждённая проблема | Исправление |
| --- | --- | --- |
| `src/controllers/AppContext/GlobalStore.js` | В production вложенные данные можно изменить, затем передать ту же ссылку в `set` без уведомления подписчиков. | Глубокая заморозка в обоих окружениях; ссылки и прототипы сохраняются. |
| `GlobalStore.js` | `Object.freeze(new Map())` не препятствует изменению содержимого. То же ограничение действует для других встроенных объектов с изменяемыми внутренними данными. Проверка только через `instanceof` пропускает объекты из другого JavaScript-контекста. | Явный отказ для Date, Map/Set и weak-вариантов, буферов/представлений, RegExp, URL/URLSearchParams. Проверка контекста не вызывает getters. |
| `GlobalStore.js` | Рекурсивная заморозка переполняет стек на глубоко вложенных данных. | Итеративный обход с поддержкой циклов, символов и неперечисляемых полей. |
| `GlobalStore.js` | `fork()` повторно нормализует уже готовое начальное значение, `reset()` тоже вызывает нормализацию. Например, нормализатор `n => n + 1` даёт разные исходные значения. | Fork без своего seed использует подготовленный снимок; reset возвращает именно этот снимок. Отдельно проверен baseline `undefined`. |
| `GlobalStore.js` | Новый подписчик, добавленный внутри уведомления, получает и текущее уведомление. | Фиксируется список слушателей для обновления; новые ждут следующего, удалённые пропускаются. |
| `src/controllers/AppContext/AppContext.js` | Серверные `UseAbstract.get/set/reset` без AppState обращаются к общему изменяемому состоянию. | Серверный доступ к `globalAppState` запрещён; нужен локальный AppState. |
| `AppContext.js` | Переданный объект `initialState` сохраняется по ссылке; замена поля до первого доступа меняет seed ленивого стора. | Поверхностная копия карты и заморозка данных при создании AppState. Сами сторы остаются ленивыми. |
| `AppContext.js` | Созданный загрузчиком AppState нельзя подключить через обычный AppContext; `value.state` перезаписывается. | Добавлен необязательный `state` prop, выбранный один раз на монтирование. |
| `AppContext.js` | Даже при неизменных входных ссылках каждый рендер создаёт новое значение контекста. | Значение контекста мемоизировано по `value` и выбранному состоянию. |

`UseAbstract.js` изменять не потребовалось: защита в `AppState.store()` охватывает
его императивные методы и hooks. Публичные методы и наследование сохранены.

## Что уже работало

- Отдельные сторы имеют собственные подписки и стабильные функции для `useSyncExternalStore`.
- `Object.is` исключает уведомления при одинаковом подготовленном значении.
- Автоматическая регистрация происходит в конструкторе; дубликат ключа уже вызывает ошибку.
- SSR-провайдер создавал отдельный AppState; исправления закрывают обход через общие императивные методы и передачу готового состояния.
- Собственные данные `UserData._state` доступны для заморозки. Приватные поля содержат сервис и служебный счётчик, поэтому менять модель не требуется.

## Зафиксированный контракт

- Состояние — примитивы, массивы, объекты и классы с наблюдаемыми данными в собственных полях. Заморозка не копирует данные, не вызывает getters и не замораживает методы или прототипы. Getters должны вычисляться из неизменяемых данных; приватные данные и побочные эффекты произвольного класса остаются ответственностью его автора.
- Нормализатор чистый. Функциональный updater получает замороженное предыдущее значение и возвращает новое. Ошибка updater/нормализации/валидации не меняет текущий снимок.
- Повторно обработанные ветви не обходятся заново: WeakSet содержит только успешно подготовленные графы. Изменяемые встроенные типы сначала проверяются во всём графе, затем начинается заморозка.
- На клиенте работа без AppContext и общий стор провайдера по умолчанию сохранены. Состояние переживает повторное монтирование такого провайдера.
- На сервере каждый запрос создаёт собственный AppState. Данные загрузчика готовы **до** `createAppState(initialState)`; `set` не используется для подготовки серверного снимка.
- `getServerSnapshot()` всегда возвращает первоначальный подготовленный снимок. При гидратации приложение передаёт те же исходные данные и само восстанавливает экземпляры моделей, если они были сериализованы.
- `AppContext.state` имеет приоритет перед `initialState`. Оба задают состояние на время монтирования; для другого состояния нужно новое монтирование.
- Обычный повторный импорт использует кэш модулей. Повторное выполнение регистрации при HMR вызывает ошибку и требует полной перезагрузки. Совместимость регистрации не угадывается; для изолированного теста можно сбросить весь граф модулей.

## Проверка

Проверено на Node.js 24.21.0 и установленном React 19.3.0, без новых зависимостей.

- **70 новых тестов проходят**: регистрация/повторные импорты, get/set/reset, нормализация, functional updates, nested/cyclic/symbol data, оба окружения, изменяемые встроенные типы и другой realm, глубокие структуры и повторное использование замороженных ветвей.
- React-интеграция проверяет StrictMode, очистку и стабильность подписок, работу внутри/вне провайдера, вложенные контексты, useSet без подписки, 500 независимых hooks и сохранение состояния на монтирование.
- SSR-тесты работают в Node без `window`: отдельные запросы, запрет общих вызовов, неизменяемые defaults и начальные снимки. DOM-тесты используют настоящий `hydrateRoot`, проверяют сохранение HTML-узла и отсутствие `onRecoverableError`, включая обновлённое текущее состояние при неизменном baseline.
- UserData сохраняет идентичность, методы, JSON и возможность приватного обновления visit-счётчика. Проверены публикация модели, смена locale через замену модели и анонимное состояние после выхода.
- Сборка Redequate ESM/CJS и обе веб-сборки проходят. В The Whisky Talks проходят 3 существующих теста в 2 файлах. Проверялись текущие checkout: demo `master`, The Whisky Talks `story/move-database-to-module`; конфигурации и исходники потребителей не менялись.

Команды:

```sh
npm run test:unit -- src/__tests__/controllers
npm run test:unit
npm run test:integration
npm run 'build core'
# В каждом веб-потребителе:
npm run build
# В The Whisky Talks:
node node_modules/vitest/vitest.mjs run --config vitest.config.mjs
```

Полный unit-набор после обновления тестов UserData: **288 успешных тестов, 23 ошибки тестов и 7 ошибок загрузки suites**.
Полный набор интеграции с локальными Auth/Database эмуляторами имеет
**34 успешных и 2 неуспешных теста**. Все эти ошибки воспроизведены в отдельной
временной копии с исходными GlobalStore/AppContext из HEAD; сравнение имён
ошибок не обнаружило новых сбоев.

Причины существующих ошибок: моки без именованного UserData; отсутствующие
импорты AppProvider и service hooks; устаревшие списки exports; SDK-моки без
authStateReady; ожидание null вместо анонимного UserData, включая два emulator
теста. Эти фикстуры требуют отдельной миграции и в данной доработке не менялись.

ESLint новых тестов и GlobalStore проходит. AppContext сохраняет три существующие
диагностики react/prop-types для value/initialState/children. Новый внутренний
prop state имеет объяснённое исключение этого правила; runtime PropTypes и
дополнительная зависимость не добавлялись.

## Регрессия логина: подготовка уведомлений после публикации

Пользовательская проверка выявила пропущенный сценарий: `Login.js` публиковал
UserData в стор, затем вызывал `setPrivate(deviceId, {notification})` и
`savePrivate()` на уже замороженной модели. Предыдущий тест публикации модели
не воспроизводил полную последовательность логина. Ошибка с read-only
deviceId воспроизведена с настоящими UserData и GlobalStore.

Исправлено:

- Настройка и сохранение уведомлений завершаются до публикации пользователя. Логин ждёт попытки подписки, её ошибки остаются нефатальными.
- Disabled-пользователь публикуется с прежним refresh и переходом в профиль; уведомления не запускаются.
- Mount-effect расположен до signed-in early return и пропускает авторизацию для уже установленного пользователя. Это устраняет `Rendered fewer hooks than expected` при переходе от анонимного состояния к авторизованному.
- Заморозка, UserData, API сторов, политика разрешений и форматы notification сохраняются; дополнительное копирование модели не добавлено.

Добавлены семь тестов реального компонента Login с настоящими UserData, service
hooks, AppContext и стором. UI, внешние сервисы и helper получения уведомлений
подменены. Проверяются успешная подписка, задержка подписки и подтверждения БД,
отказ в разрешении, disabled-пользователь, iOS, первый логин и пропуск повторной
авторизации. Все семь тестов и 70 тестов состояния проходят. При замене только
Login.js на исходный файл из HEAD пять тестов падают, в том числе на нарушении
порядка hooks и отсутствии сохранённого notification.

Проверки: framework ESM/CJS, обе веб-сборки и три smoke-теста The Whisky Talks
проходят. Полный unit-набор имеет те же существующие сбои. Новые тесты проходят
ESLint; существующие диагностики Login не исправлялись. Firebase emulator-тесты
в этой поправке повторно не запускались: сетевые адаптеры не менялись, их прежние
результаты выше относятся к исходному аудиту состояния. Реальный браузерный
логин и запрос разрешения уведомлений остаются отдельной ручной проверкой.

## Обновление тестов UserData и provider timestamps

После удаления SERVER_TIMESTAMP/constants.js устаревший импорт блокировал
загрузку UserData unit-suite, а тест состояния использовал отсутствующий export.
Оба импорта удалены. Фикстуры теперь задают собственный database.TIMESTAMP;
common-модель проверяется напрямую для ролей, getters, JSON и числовых дат.

Веб-контроллер интерпретирует только точную ссылку database.TIMESTAMP и передаёт
обычные даты common-модели. Добавлена согласованная защита от отсутствующего
database; undefined/пустые даты не превращаются в текущее время. Проверены
пустые и числовые timestamps без database, provider-маркер и отдельный объект
такой же формы, а также независимость вложенного JSON экспорта.

Functions common.test.js обновлён под отсутствие SERVER_TIMESTAMP, создание
через new и расширение через subclass/_getState(). Изоляция экземпляров и
исключение служебного состояния из JSON проверяются без браузера или database.

Результаты: 17 UserData unit-тестов, 77 state/Login-тестов, все 33 UserData
emulator-теста и пять Functions common-тестов проходят. Web/server ESM/CJS
сборки успешны; обновлённые framework unit-тесты проходят ESLint. Полные unit
и emulator-наборы сохраняют те же прежние сбои Auth/UI. Для Functions использован
временный каталог с новой server-сборкой под именем redequate; рабочие
vendor/redequate-server.tgz и lockfile не менялись. Для запуска обновлённого
теста против установленного архива нужен обычный refresh server-пакета.

## Сознательно не выполнялось

- Библиотеки управления состоянием, глубокое копирование, wrappers/Proxy для встроенных типов, производные состояния и графы зависимостей.
- Переиспользование несовместимой регистрации, перенос состояния при HMR и новый lifecycle manager.
- Сериализатор моделей, автоматическая передача SSR-снимка и полный SSR Dispatcher/приложений.
- Смена сборочной системы, перенос прочих Redux-состояний и исправление посторонних старых тестовых фикстур.
- Изменения сетевых API, Firebase-форматов и Android-моста. Нативный Android и реальные браузерные авторизация/гидратация приложений отдельно не запускались; проверены state-layer интеграция, модели и сборки потребителей.
